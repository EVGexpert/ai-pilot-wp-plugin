# Changelog

## 2.3.0 — 2026-08-12

### Added
- `/agent/connect-code` now stores site metadata alongside the one-time code: `plugin_version`, `wp_version`, `capabilities`, `instance_id` (site ID hash), `hostname` (normalized lowercase), and `created_at`.
- `/agent/verify-code` response extended with `plugin_version`, `wp_version`, `capabilities`, `instance_id`, `hostname`, and `expires_at` (ISO 8601 UTC), sourced from the connect-code record.

### Compatibility
- Existing verify-code fields (`verified`, `site_url`, `site_name`, `token`) are unchanged — auth-api 0.5.x clients continue to work without modification.
- All new verify-code fields are optional: codes generated by plugin 2.2.2 (without metadata) are handled via fallbacks, so an in-flight reconnect across the upgrade boundary does not break.
- Connect-code mechanics (one-time use, 5-minute expiry, crypto-random token, admin-only generation) are unchanged.

## 2.2.2 — 2026-07-28

### Fixed
- Categories now accept IDs, names, mixed arrays and comma-separated strings.
- Missing named categories are created before assignment.
- Tags now accept IDs, names, mixed arrays and comma-separated strings.
- Singular `category` / `tag` fields are normalized to `categories` / `tags`.
- Category and tag changes are applied by the actual monolithic runtime used in production.
- Direct post create/update endpoints use the same taxonomy normalization.
- Post updates can explicitly clear categories and tags.

### Compatibility
- Preserves the 2.2.0 proposal/approve execution contract and idempotent replay.
- Preserves the top-level AI Pilot admin interface and one-click connection flow.
- Keeps both `aipilot/v1` and `openclaw/v1` REST namespaces.

### Packaging
- Full package uses the same top-level folder as the previous working source archive.
- Version 2.2.1 is withdrawn and should not be activated.

## 2.2.0 — 2026-07-27

### Added
- Top-level **AI Pilot** section in the WordPress admin menu.
- **Open AI Pilot** shortcut in the WordPress Plugins list.
- Modern onboarding dashboard with connection, assistant, permissions and system pages.
- One-click connect flow with a five-minute one-time code.
- Automatic popup close and dashboard transition after successful authorization.
- Admin-only connection status endpoint for safe polling.
- Executable proposal approval flow with stored results and idempotent replay.
- Canonical action result format for `create_post`.
- Validation for title, content and post status before WordPress writes.

### Changed
- Connection tokens remain provisional until the one-time code is verified.
- Reconnect no longer invalidates a working token before authorization completes.
- `/agent/approve/{id}` now executes the saved action instead of only changing status.
- `/agent/action` remains available for legacy clients and uses the same action executor.
- Legacy Settings URL redirects to the new top-level admin section.

### Security
- Connect-code creation and connection-status polling require a WordPress administrator and REST nonce.
- Approval executes only the action and params saved in the proposal.
- Repeated approval returns the stored result and does not create a duplicate post.
- A database-backed per-proposal lock blocks simultaneous approve requests.
- Disconnect revokes the active token and removes pending connection codes.
